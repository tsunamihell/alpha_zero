# MCTS follow-up bug fixes — 2026-11-10

Scope: `alpha_zero/core/mcts_v1.py`, `mcts_v2.py`, shared sampling/validation
helpers, regression tests, and the test runner. Existing unrelated working-tree
changes and staged game-data deletions were preserved.

## Reproduced defects and corrections

- Warm-up sampling could loop forever when only pass had positive visit probability,
  including positions where pass was the only legal move. Sampling now masks pass
  only when another legal move exists, renormalizes, and uses a uniform legal fallback
  if all remaining visit probabilities are zero. The returned training policy remains
  the search visit distribution, as before.
- Parallel search leaked virtual losses when selection or batched inference raised.
  All reservations, including repeated reservations of one leaf, now unwind in
  `finally`. Tests verify the same tree can be searched again after an inference error.
- Short/empty evaluator batches were silently truncated by `zip`; empty batches could
  cause indefinite retries. Both batch lengths are now checked before processing.
- Boolean, fractional and infinite simulation budgets passed the old positivity check.
  Both versions now require positive integer budgets; v1 also validates `num_parallel`.
- A single simulation in v1 produced an all-zero search policy. It now guarantees a
  child visit, matching the earlier v2 correction. Reused, unexpanded v1 roots are
  evaluated before adding root noise, including an unvisited warm-up fallback move.

3x3 Gomoku games using tree reuse and root noise across both implementations and
both search modes. Failure-path tests bound retries instead of hanging the test runner.
